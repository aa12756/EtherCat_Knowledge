## 1. 三个字段分别是什么

| 超控界面 | 协议参数 | 含义 | Hsl / TIA 对照 |
|----------|----------|------|----------------|
| **数据块** | `db_num` | DB 块号，如 DB1 → **1** | `DB1.x` 中的 **1** |
| **起始位置** | `starting_address` | 从该 DB **第几个字节**开始 `db_read`（**从 0 起**） | `DB1.0` → 起始 **0**；`DB1.5` → 起始 **5** |
| **偏移量** | `offset` | 在 hw-cc 中**主要给 BOOL 用**：在所读字节内的 **位 0～7** | `DB1.DBX10.3` → 起始 **10**，偏移 **3** |

底层两步：

1. `db_read(db_num, starting_address, size)` — 从 PLC 拉一段原始字节到 buffer。  
2. `get_data(buffer, plc_data_type, offset)` — 按类型从 buffer 解析数值。

**字节地址**靠「数据块 + 起始位置」；**BOOL 的位号**靠「偏移量」。

---

## 2. 一个字节与 BOOL 寻址

一个字节 = **8 个位**（常记为位 0～7，对应 TIA `DBX` 的 `.0`～`.7`）：

```text
字节地址 10（DB1 的第 10 个字节）

  位7  位6  位5  位4  位3  位2  位1  位0
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ 0 │ 1 │ 0 │ 0 │ 1 │ 0 │ 0 │ 1 │
└───┴───┴───┴───┴───┴───┴───┴───┘
```

- **BOOL**：只占其中 **1 位**（工位就绪、报警、握手等常挤在同一字节）。  
- **BYTE**：占 **整字节**（0～255，如工件类型码），不按「位」解析。

---

## 3. TIA 写法 → 超控怎么填

| TIA 符号 | 含义 | 超控填法 |
|----------|------|----------|
| `DB1.DBX10.0` | DB1 第 **10 字节** 的第 **0 位** | 数据块 **1**，起始 **10**，类型 **bool**，偏移 **0** |
| `DB1.DBX10.3` | 同上字节，第 **3 位** | 数据块 **1**，起始 **10**，类型 **bool**，偏移 **3** |
| `DB1.DBB10` | DB1 第 **10 字节**整字节 | 数据块 **1**，起始 **10**，类型 **byte**，偏移 **0** |
| `DB1.DBB1` | DB1 第 **1 字节** | 数据块 **1**，起始 **1**，类型 **byte**，偏移 **0** |

规律：

- `DBX` 的数字（如 10）→ **起始位置**。  
- `DBX` 点后的数字（如 `.3`）→ **偏移量**（仅 bool 生效）。  
- `DBB` 只有字节号，无 `.位` → **偏移量填 0**。

---

## 4. 「偏移量」设计是为了什么场景

在 `hardware_cc/.../s7.py` 中，**只有 `bool` 分支使用 `offset`**：

```python
# 读
snap7.util.get_bool(reading, 0, offset)
# 写
snap7.util.set_bool(reading, 0, offset, data)
```

**典型场景**：多个 BOOL 共用同一字节，节省 DB 空间。

| 变量（示例） | 起始 | 偏移 | TIA |
|--------------|------|------|-----|
| 工位就绪 | 10 | 0 | DBX10.0 |
| 报警 | 10 | 1 | DBX10.1 |
| 握手应答 | 10 | 2 | DBX10.2 |

同一 **起始 10**，用不同 **偏移** 区分点位。

超控 **bool / int / byte 共用一套表单**，所以界面上 **偏移量始终显示**；底层 **仅 bool 消费该字段**。

## 5. byte 与偏移量：为什么 offset=1 不会变成 DB1.1

### 5.1 实现行为

对 `plc_data_type == "byte"`：

```python
result = snap7.util.get_usint(reading, 0)   # 固定从 buffer 下标 0 解析
```

- `db_read(1, 0, 1)` → 始终读 **DB1 字节 0**（等价 Hsl **`DB1.0`**）。  
- **`offset` 不参与 byte 的解析**；日志里可能出现 `offset=1`，但 PLC 侧仍是 **DB1.0**。  
- 要读 **DB1.1** → 改 **`starting_address: 1`**，**不是** `offset: 1`。

### 5.2 与「误以为」的对比

| 误以为 | 实际（当前 s7.py） |
|--------|---------------------|
| 起始 0 + 偏移 1 = 读 DB1.1 | 仍读 **DB1.0**，偏移对 byte **无效** |
| 偏移量 =「字节再往后挪」 | **字节挪位**只改 **起始位置** |

### 5.3 配置建议（工件类型 BYTE）

| 字段 | 建议 |
|------|------|
| 数据块 | 与 TIA `DBB` 块号一致 |
| 起始位置 | 与 TIA `DBB` 字节号一致 |
| 偏移量 | **0**（避免与 bool 位偏移混淆） |
| 数据类型 | **byte**（勿用 int 代替） |

## 6. BOOL 与 byte 配置对照（速查）

| 类型 | 起始位置 | 偏移量 |
|------|----------|--------|
| bool | TIA **字节**号（DBX 前数字） | TIA **.位**（0～7） |
| byte | TIA **DBB 字节**号 | **0** |
| int / 等 | 类型起始 **字节**号 | **0**（当前实现多数类型也不使用 offset） |

---

## 7. 与 Hsl 模拟器 / S7-1500 联调

连接：`127.0.0.1:102`，`rack/slot` 与超控 `device_config` 一致。

| 超控变量 | Hsl Demo 单点地址 | 操作 |
|----------|-------------------|------|
| `db_num=1, starting_address=0, byte` | **`DB1.0`** | **byte读取 / byte写入** |
| `db_num=1, starting_address=1, byte` | **`DB1.1`** | 同上 |

- 超控走 **DB 区**，不要只用 **M 区** 与 DB 变量对照。  
- 写 byte 用 **byte写入**，值 **0～255**；勿用 **int写入** 测 BYTE 点。

---

## 8. 练习对照

1. 报警位 `DB1.DBX0.7` → 块 **1**，起始 **0**，**bool**，偏移 **7**  
2. 工件类型 `DB1.DBB0` → 块 **1**，起始 **0**，**byte**，偏移 **0**  
3. 第二个工件类型 `DB1.DBB1` → 块 **1**，起始 **1**，**byte**，偏移 **0**（**不是** 起始 0 + 偏移 1）

---

## 9. BYTE 与 INT 不可混用（需求背景摘要）

| 要点 | BYTE | INT（超控 `int`） |
|------|------|-------------------|
| 占用 | **1 字节** | **2 字节** |
| 符号 | **无符号 0～255** | **有符号** |
| 配置 | `plc_data_type: "byte"` | `plc_data_type: "int"` |

工件类型在 PLC 为 **BYTE** 时，超控必须配 **byte**；误配 **int** 会按 2 字节有符号读写，与 TIA 不一致。详见 [S7_byte_改动说明.md](./S7_byte_改动说明.md)。
