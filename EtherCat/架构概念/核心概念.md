# EtherCAT 核心概念

---

## 一、PDO 和 SDO

### PDO（Process Data Object）— 过程数据对象

用于主站与从站之间 **周期性、实时** 的数据交换，传输控制指令和状态反馈。

| 特性 | 说明 |
|------|------|
| **通信方式** | 广播式，主站一发，所有从站沿环形逐帧处理 |
| **传输周期** | 固定周期（如 1kHz / 4kHz / 8kHz），与控制循环同步 |
| **数据内容** | 实时控制数据：目标位置 / 速度 / 转矩、实际位置 / 状态字等 |
| **优先级** | **高** — 占用专用通道，不受 SDO 影响 |
| **触发方式** | 同步（SYNC 事件触发）或异步（自由运行） |
| **PDO 映射** | 通过配置 PDO 映射表决定每个从站收发哪些对象 |

**典型 PDO 数据流（CSP 模式）：**

```
主站 ──→ 从站： 控制字(0x6040) + 目标位置(0x607A) + 目标速度(0x60FF) + 模式(0x6060)
从站 ──→ 主站： 状态字(0x6041) + 实际位置(0x6064) + 实际速度(0x606C) + 状态码(0x603F)
```

**查看方法：**

```bash
# 查看当前 PDO 映射
ethercat pdos

# 查看 SDO 对象字典（PDO 映射配置在 0x1600-0x1B00）
ethercat upload -p <slave> 0x1A00 0
```

---

### RxPDO 与 TxPDO

PDO 按数据流向分为 **RxPDO（Receive PDO）** 和 **TxPDO（Transmit PDO）**，分别对应主站到从站和从站到主站的数据通道。

| 特性            |                   RxPDO（接收 PDO）                    |                   TxPDO（发送 PDO）                   |
| ------------- | :------------------------------------------------: | :-----------------------------------------------: |
| **全称**        |            Receive Process Data Object             |           Transmit Process Data Object            |
| **方向**        |                **主站 → 从站**（主站下发指令）                 |                **从站 → 主站**（从站上报数据）                |
| **别名**        |                 输出 PDO（Output PDO）                 |                 输入 PDO（Input PDO）                 |
| **典型数据**      | 控制字(0x6040)、目标位置(0x607A)、目标速度(0x60FF)、运行模式(0x6060) | 状态字(0x6041)、实际位置(0x6064)、实际速度(0x606C)、故障码(0x603F) |
| **ESC 通道**    |                   SM2（同步管理器通道 2）                   |                  SM3（同步管理器通道 3）                   |
| **PDO 映射寄存器** |             0x1600–0x17FF（RxPDO 映射对象）              |             0x1A00–0x1BFF（TxPDO 映射对象）             |
| **SM 通道寄存器**  |                  0x1C12（RxPDO 分配）                  |                 0x1C13（TxPDO 分配）                  |
| **数量限制**      |               每个从站最多 **16 个** RxPDO                |               每个从站最多 **16 个** TxPDO               |

**数据流示意：**

```
主站（IgH）
  │
  ├── RxPDO ──→ SM2 ──→ 从站 MCU（控制指令：目标位置、控制字等）
  │                     从站执行器（电机、阀、IO 输出）
  │
  └── TxPDO ←── SM3 ←── 从站 MCU（状态反馈：实际位置、故障码等）
                          从站传感器（编码器、IO 输入）
```

**配置查看：**

```bash
# 查看所有 PDO（会列出 RxPDO 和 TxPDO 的映射详情）
ethercat pdos

# 查看从站 1 的 RxPDO 映射（0x1600）
ethercat upload -p 1 0x1600 0

# 查看从站 1 的 TxPDO 映射（0x1A00）
ethercat upload -p 1 0x1A00 0

# 查看 RxPDO 分配（0x1C12）
ethercat upload -p 1 0x1C12 0
```

> **记忆要点**：RxPDO 的 R = Receive（接收），从从站角度看是"接收"主站发来的指令；TxPDO 的 T = Transmit（发送），从从站角度看是"发送"数据给主站。

---

### SDO（Service Data Object）— 服务数据对象

用于主站与从站之间 **非周期性、按需** 的数据交换，主要用于参数配置、诊断和初始化。

| 特性 | 说明 |
|------|------|
| **通信方式** | 点对点，主站发起请求，从站应答（邮箱 Mailbox） |
| **传输周期** | 按需触发（上电初始化 / 故障诊断 / 参数调整时使用） |
| **数据内容** | 配置参数：PID 系数 / 软限位 / 电子齿轮比 / 厂商自定义参数等 |
| **优先级** | **低** — 通过邮箱通道传输，不干扰 PDO 实时循环 |
| **传输协议** | 分段传输（数据 > 4 字节时自动分段）或快速传输（≤ 4 字节） |
| **寻址方式** | 通过对象字典索引（16 位）+ 子索引（8 位） |

**典型 SDO 使用场景：**

```
上电阶段： SDO 写入电机参数（电子齿轮比、电流限幅、软限位）
运行阶段： SDO 读取故障码、温度、厂商诊断信息
停机阶段： SDO 保存参数到 EEPROM
```

**查看方法：**

```bash
# 读取从站对象字典
ethercat upload -p <slave> <index> <subindex>

# 写入从站对象字典
ethercat download -p <slave> <index> <subindex> <value>

# 示例：读取从站 1 的设备名称（0x1008, 子索引 0）
ethercat upload -p 1 0x1008 0
```

---

### PDO vs SDO 对比

| 特性              |         PDO         |         SDO         |
| --------------- | :-----------------: | :-----------------: |
| **全称**          | Process Data Object | Service Data Object |
| **用途**          |       实时过程数据        |       参数配置数据        |
| **通信方式**        |         周期性         |        事件触发         |
| **实时性**         |       高（μs 级）       |       低（ms 级）       |
| **优先级**         |          高          |          低          |
| **数据量**         |     小（1-64 字节）      |    大（1-4096 字节）     |
| **方向**          |      固定（输入/输出）      |       双向（读/写）       |
| **映射**          |        预先配置         |        动态访问         |
| **传输通道**        |     过程数据通道（专用）      |    邮箱通道（Mailbox）    |
| **触发方式**        |   SYNC 同步 / 自由运行    |       主站主动请求        |
| **典型应用**        |     位置/速度/转矩指令      |      读取参数/修改配置      |
| **通信协议**        |       无额外协议开销       |    SDO 协议（分段/快速）    |
| **对实时性影响**      |       无（专用通道）       |      不影响（后台通道）      |
| **EtherCAT 命令** |      逻辑寻址（广播）       |      物理寻址（单个）       |

### 关键要点

1. **PDO 是"油门"**，SDO 是"维修手册" — PDO 跑实时控制，SDO 做配置诊断
2. PDO 映射在初始化阶段通过 SDO 配置（写入 `0x1C12`/`0x1C13` 等寄存器）
3. 生产运行中应**尽量少用 SDO**，避免邮箱通道阻塞影响紧急通信
4. CoE（CANopen over EtherCAT）协议层定义了 PDO/SDO 的行为规范

## 二、ESI 和 ENI 文件

### ESI（EtherCAT Slave Information）— 从站信息文件

ESI 是从站设备制造商提供的 **XML 描述文件**，定义了从站设备的能力和特性，是配置工具识别和配置从站的依据。

| 特性 | 说明 |
|------|------|
| **格式** | XML（.xml），部分厂商打包为 .esi |
| **提供方** | 从站设备制造商（如 Beckhoff、Omron、Panasonic 等官网下载） |
| **用途** | 配置工具解析从站能力，生成网络配置 |
| **存储位置** | 配置工具（如 TwinCAT、IgH）的 ESI 库目录 |

**ESI 文件包含的内容：**

```
<Device>
  ├── 基本信息：厂商名称、设备名称、版本号、图片
  ├── 对象字典：所有 SDO 对象定义（索引、子索引、类型、默认值）
  ├── PDO 映射：默认的 TxPDO / RxPDO 映射配置
  ├── 同步管理器（SyncManager）：PDO 和 Mailbox 通道定义
  ├── DC 同步（Distributed Clock）：是否支持 DC，支持的模式
  └── FMMU：现场总线内存管理单元配置
```

**典型路径（IgH）：**

```bash
# IgH 的 ESI 文件存放目录
/usr/local/etherlab/etc/ethercat/esi/

# 查看已安装的 ESI 文件
ls /usr/local/etherlab/etc/ethercat/esi/

# 通过 ethercat 命令查看从站设备信息（基于 ESI 解析）
ethercat slave -v
```

> ESI 相当于从站设备的"身份证 + 说明书"。

---

### ENI（EtherCAT Network Information）— 网络信息文件

ENI 是描述 **整个 EtherCAT 总线网络拓扑和配置** 的文件，由配置工具基于 ESI 文件生成，供主站在启动时加载。

| 特性 | 说明 |
|------|------|
| **格式** | XML（TwinCAT / IgH）或二进制（部分实现） |
| **生成方式** | 由配置工具扫描实际总线后自动生成 |
| **用途** | 主站启动后按 ENI 配置初始化所有从站 |
| **载体** | IgH 中通常以 .xml 形式存储，运行时加载 |

**ENI 文件包含的内容：**

```
<EtherCATConfig>
  ├── 总线拓扑：从站顺序、连接关系、物理端口
  ├── 每个从站的配置：Vendor ID、Product Code、站地址
  ├── PDO 映射：每个从站的 TxPDO / RxPDO 具体映射项
  ├── DC 配置：同步模式、循环时间、偏移时间
  ├── 同步管理器：SM 通道的分配（0-1 Mailbox，2-3 PDO）
  └── FMMU：逻辑地址空间到物理设备的映射
```

**IgH 中生成和使用 ENI：**

```bash
# 方法 1：ethercat 命令生成（需要完整总线拓扑）
ethercat config > /etc/ethercat/eni.xml

# 方法 2：使用 xml 配置工具（如 etherlab）生成
# 手动编写或使用工具生成 network-config.xml

# 方法 3：IgH 源码中的示例工具
# 路径：igh-master/tool/ 下的配置生成脚本

# 指定 ENI 文件加载（修改 ethercat.conf）
sudo vim /etc/sysconfig/ethercat
# 添加配置：
# ENI_FILE=/etc/ethercat/eni.xml
```

---

### ESI vs ENI 对比

| 对比维度     |            ESI             |             ENI              |
| -------- | :------------------------: | :--------------------------: |
| **全称**   | EtherCAT Slave Information | EtherCAT Network Information |
| **描述对象** |         单个从站设备的能力          |          整个总线的拓扑和配置          |
| **格式**   |            XML             |          XML / 二进制           |
| **来源**   |           制造商提供            |        配置工具基于 ESI 生成         |
| **修改频率** |       极低（更换硬件型号时才变）        |       频繁（每次改拓扑/映射都要更新）       |
| **角色**   |          设备的"说明书"          |          整条总线的"施工图"          |
| **谁消费它** | 配置工具（TwinCAT / IgH Config） |        EtherCAT 主站驱动         |
| **包含内容** |        设备描述、PDO 定义         |         拓扑、地址、映射、同步          |
| **文件数量** |           每个从站一个           |            整个系统一个            |

### 关键要点

1. **ESI → ENI 的转化链路**：制造商提供 ESI → 配置工具扫描总线 → 生成 ENI → 主站加载 ENI
2. 更换从站设备型号后，必须更新 ESI 库并重新生成 ENI
3. IgH 中可以通过 `ethercat config` 或 xml 模板生成 ENI，TwinCAT 中自动管理
4. 调试时遇到从站无法进入 OP 状态，通常是 ENI 与物理总线不一致（拓扑变化或 PDO 映射不匹配）
5. ESI 文件缺失时，从站会被识别为 "Vendor specific" 设备，无法正确配置 PDO

## 三、ESC 内部硬件模块

EtherCAT 从站设备的核心是 **ESC（EtherCAT Slave Controller）芯片**，如 LAN9252、AX58100、ET1100 等。以下模块均位于 ESC 芯片内部或直连在芯片周围。

### MCU（Microcontroller Unit）— 从站微控制器

MCU 是从站的"大脑"，负责运行从站固件，处理 EtherCAT 数据并控制外部设备（电机、IO 等）。

| 特性 | 说明 |
|------|------|
| **位置** | 独立于 ESC 芯片之外，通过 SPI / 并行总线 / 16 位总线与 ESC 通信 |
| **角色** | ESC 负责通信，MCU 负责应用（电机控制算法、IO 逻辑、故障处理） |
| **典型型号** | STM32（ARM Cortex-M）、TI C2000（DSP）、Infineon XMC、FPGA |
| **交互方式** | 读写 ESC 内部共享 RAM（通过 SM 保障数据一致性） |
| **固件功能** | 解析 RxPDO（控制字+目标位置等）、执行控制算法、更新 TxPDO（状态字+实际位置等） |

**与 ESC 的通信关系：**

```
┌─────────────────────┐      SPI / 并行        ┌──────────────────────┐
│   ESC 芯片           │ ◄──────────────────► │   MCU                │
│   (如 LAN9252)       │     共享 RAM 交互       │   (如 STM32)          │
│                      │                        │                      │
│  ┌── SM0  Mailbox Out│                        │  读取 RxPDO → 控制电机│
│  │ SM1  Mailbox In   │                        │  采集编码器 → 写 TxPDO│
│  │ SM2  RxPDO        │                        │  异常检测 → 故障处理   │
│  │ SM3  TxPDO        │                        │                      │
│  └── FMMU 地址映射    │                        │                      │
└─────────────────────┘                        └──────────────────────┘
```

> **关键点**：ESC 负责"通信"，MCU 负责"应用" — 主站发来的位置指令由 MCU 解析并执行伺服控制算法，而非 ESC 完成。

---

### EEPROM（Electrically Erasable Programmable Read-Only Memory）— 物理存储芯片

EEPROM 是焊接在从站板卡上的**物理存储芯片**，通过 **I²C 或 SPI 总线** 连接到 ESC，出厂时已烧录了从站的自描述信息。

| 特性 | 说明 |
|------|------|
| **位置** | ESC 外部，通过 I²C/SPI 总线连接 |
| **典型型号** | 24LC64（Microchip，64Kbit）、FM24C64（铁电，更快的写入寿命） |
| **容量** | 通常 1Kbit ~ 64Kbit（128 ~ 8192 字节） |
| **烧录方式** | 厂商出厂烧录，也可通过主站 `ethercat sii_write` 命令在线烧录 |
| **保存内容** | ESI 文件对应的二进制数据（见下方列表） |

**EEPROM 存储内容：**

| 数据段          |    长度    | 内容                                             | 作用                   |
| ------------ | :------: | ---------------------------------------------- | -------------------- |
| **ESC 配置区**  | 前 128 字节 | FMMU 通道数、SM 通道数、DC 能力、是否支持 FoE 等               | 主站知道如何配置该从站的 ESC 寄存器 |
| **厂商信息区**    |    可变    | Vendor ID、Product Code、Revision No.、Serial No. | 唯一标识该从站型号            |
| **邮箱配置**     |    可变    | Mailbox 最大大小、支持的协议（CoE/SoE/AoE/...）            | 配置 SDO 通信参数          |
| **PDO 默认映射** |    可变    | 出厂默认的 RxPDO/TxPDO 映射配置                         | 主站可直接用，也可以重映射        |
| **SM 配置**    |    可变    | SM0~SM3 的默认地址、长度、控制寄存器值                        | 邮箱和过程数据通道的默认配置       |

**上电自举流程：**

```
ESC 上电复位
    │
    ├── 通过 SII（I²C）自动读取 EEPROM 前 128 字节
    │   → 获取 ESC 基础配置（FMMU/SM 数量等）
    │
    ├── 后续由主站通过 FoE 或寄存器读写完整 EEPROM
    │   → 主站获取厂商信息 / PDO 映射 / 邮箱配置
    │
    └── 主站匹配 ESI 文件，生成 ENI，配置从站
```

---

### SII（Slave Information Interface）— 从站信息接口

SII **不是独立芯片**，而是 **ESC 芯片内部的硬件逻辑模块**，负责自动读取外部 EEPROM 中的数据并供主站访问。

| 特性 | 说明 |
|------|------|
| **本质** | ESC 内部的数据读取控制器（硬件状态机） |
| **物理层** | 连接 EEPROM 的 I²C/SPI 控制器 |
| **触发方式** | 上电自动读取 EEPROM 前 128 字节；主站可通过寄存器请求读取完整数据 |
| **对外接口** | 主站通过 EtherCAT 帧的 **SII 读写命令**（寄存器 0x502 ~ 0x50F）访问 SII 数据 |

**主站访问 SII 的流程：**

```bash
# IgH 通过底层寄存器访问 SII，用户态命令为：
ethercat sii_read -p 1        # 读取从站 1 的完整 SII 数据（EEPROM 内容）
ethercat sii_write -p 1 data.bin  # 写入 SII 数据（烧录 EEPROM）

# 也可以直接读取 SII 相关寄存器
ethercat reg_read -p 1 0x0502   # SII 状态/控制寄存器
```

**三者的实物关系：**

```
  ESI 文件 (.xml)                  ← 开发阶段用的"图纸"
     │  内容相同（二进制格式不同）
     ▼
  EEPROM（物理芯片）                ← 出厂烧录到从站板卡上
     │
  SII 接口（ESC 内部硬件）           ← 上电自动读取 + 主站按需读取
     │
  主站获得从站信息                  ← 枚举阶段识别设备
```

---

### SM（SyncManager）— 同步管理器

SM 是 **ESC 芯片内部的硬件通道**，用来控制主站和 MCU **对共享内存的访问权限**，确保数据一致性和完整性。

**典型配置（标准 4 通道）：**

| 通道 | 方向 | 用途 | 通信类型 | ESC RAM 地址（典型） |
|:----:|:----:|------|:--------:|:------------------:|
| **SM0** | 主站 → 从站 | 邮箱输出（Mailbox Out） | SDO | 0x1000 |
| **SM1** | 从站 → 主站 | 邮箱输入（Mailbox In） | SDO | 0x1400 |
| **SM2** | 主站 → 从站 | 过程数据输出（RxPDO） | PDO | 0x1800 |
| **SM3** | 从站 → 主站 | 过程数据输入（TxPDO） | PDO | 0x1A00 |

**SM 的 3 个核心机制：**

| 机制 | 说明 |
|------|------|
| **握手机制** | 写完后通知读方，读完后通知写方"可以继续写了" |
| **数据一致性保护** | 一方正在读取时，另一方不可以写入，避免读到半残数据 |
| **中断通知** | 数据到达 / 数据取走后触发中断信号通知 MCU |

**典型读写时序：**

```
主站                          ESC                           MCU
 │                             │                             │
 ├── 写 SM2 RAM (RxPDO) ──────►│                             │
 │                             ├── 中断通知 MCU ────────────►│
 │                             │                             ├── 读取 SM2 数据
 │                             │                             ├── 执行控制算法
 │                             │                             ├── 写 SM3 RAM (TxPDO)
 │                             │◄── 中断通知主站 ────────────┤
 ├── 读 SM3 RAM (TxPDO) ◄─────│                             │
 │                             │                             │
```

> **类比**：SM 就像房间之间的**带锁传递窗** — 主站放好数据锁上 → 通知 MCU → MCU 开锁取走 → 放回复数据锁上 → 通知主站来取。

---

### FMMU（Fieldbus Memory Management Unit）— 现场总线内存管理单元

FMMU 是 **ESC 芯片内部做地址映射的硬件单元**，负责将 **主站侧的逻辑地址** 映射到 **从站侧的本地物理地址**。

**为什么需要 FMMU？**

EtherCAT 数据帧使用**逻辑寻址** — 主站构建一个连续的 4GB 逻辑地址空间，每个从站被分配一段区间：

```
主站构建的 EtherCAT 数据帧（逻辑寻址）：
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│  报头     │ 数据段 A   │ 数据段 B   │ 数据段 C   │ 报尾     │
└──────────┴─────┬────┴─────┬────┴─────┬────┴──────────┘
                 │          │          │
           ┌─────┘    ┌────┘    ┌────┘
           ▼          ▼         ▼
       Slave 1    Slave 2    Slave 3
     FMMU命中段A  FMMU命中段B  FMMU命中段C
```

**FMMU 的工作流程：**

| 步骤 | 动作 |
|:----:|------|
| 1 | 主站扫描完成后，给每个从站分配逻辑地址段 |
| 2 | 主站将地址分配写入每个从站的 FMMU 寄存器 |
| 3 | 运行时，每个 EtherCAT 帧经过从站时，FMMU 检查是否命中其区间 |
| 4 | 命中 → 从帧中提取数据（输出）或插入数据（输入） |
| 5 | 不命中 → 不做任何操作，直接转发给下一个从站 |

**典型寄存器配置（每个 FMMU 通道）：**

```
FMMUx 寄存器组（约 16 字节）：
├── 逻辑起始地址 (4 字节)  — 在 4GB 逻辑空间中的起始位置
├── 长度 (2 字节)          — 占用的位数
├── 逻辑起始位 (1 字节)    — 在起始地址中的 bit 偏移
├── 数据起始位 (1 字节)    — 在本地物理地址中的 bit 偏移
├── 本地物理起始地址 (2 字节) — 映射到 ESC 内部 RAM 地址
└── 控制/状态 (1 字节)     — 使能位、方向位（读/写）
```

**不同 ESC 芯片的 FMMU 数量：**

| 芯片型号 | FMMU 通道数 |
|----------|:----------:|
| LAN9252 | 3 |
| AX58100 | 8 |
| ET1100 | 8 |
| ET1200 | 3 |

```
主站应用程序
     │
     ▼
主站网卡 (如 I226-V)
     │
     ▼  EtherCAT 数据帧（逻辑寻址）
     │
┌────┴─────────────────────────────┐
│  ESC 芯片 (LAN9252 / AX58100)     │
│                                   │
│  ① FMMU：检查帧地址是否命中本从站   │
│     命中 → 提取 RxPDO 数据段       │
│                                   │
│  ② SM2：握手保护，通知 MCU 来取    │
│                                   │
│  ③ MCU 读取 SM2 RAM：             │
│     拿到 控制字(0x6040)            │
│          + 目标位置(0x607A)         │
│                                   │
│  ④ MCU 执行伺服控制算法            │
│     位置环 → 速度环 → 电流环       │
│                                   │
│  ⑤ MCU 写 SM3 RAM：              │
│     填入 状态字(0x6041)            │
│          + 实际位置(0x6064)         │
│                                   │
│  ⑥ SM3：通知主站数据已就绪         │
│                                   │
│  ⑦ FMMU：将 TxPDO 数据插入帧位置   │
└────┬─────────────────────────────┘
     │
     ▼ EtherCAT 帧继续转发到下一从站
     │
     ▼
主站收到帧，提取所有从站的 TxPDO 数据
```

### 分层架构总览

ESC 周边模块按层次关系分为三层：

```
┌─────────────────────────────────────────────────────┐
│                  应用层 (Application)                  │
│  ┌──────────────────────────────────────────────────┐│
│  │                    MCU                           ││
│  │        (运行固件，解析 RxPDO，执行控制算法)            ││
│  └──────────────────────────────────────────────────┘│
├─────────────────────────────────────────────────────┤
│              ESC 芯片内部硬件 (数据路由层)                │
│  ┌─────────┐  ┌──────────┐  ┌───────────────────┐  │
│  │   SII    │  │   FMMU   │  │      SM ×4        │  │
│  │ (读身份)  │  │ (地址映射)  │  │ (0,1邮箱 / 2,3数据)│  │
│  └────┬────┘  └──────────┘  └───────────────────┘  │
├───────┴─────────────────────────────────────────────┤
│              物理层 (Physical)                        │
│  ┌──────────────┐                                    │
│  │    EEPROM    │        其他外设 (编码器 / IO / 电机)    │
│  │  (存储身份信息) │                                    │
│  └──────────────┘                                    │
└─────────────────────────────────────────────────────┘
```

**各模块与文档前后章节的对应关系：**

| 章节 | 模块 | 关联 |
|:----:|------|------|
| 一、PDO/SDO | **SM2/SM3** = PDO 通道，**SM0/SM1** = SDO 邮箱通道 | SM 是 PDO/SDO 在 ESC 内的承载通道 |
| 二、ESI/ENI | **EEPROM/SII** | ESI 文件内容 = EEPROM 烧录数据，SII 是读取接口 |
| 三、本节 | EEPROM → SII → FMMU → SM → MCU | 物理存储 → 读取 → 映射 → 同步 → 应用 |

### EEPROM（Electrically Erasable Programmable Read-Only Memory）— 物理存储芯片

#### 是什么

EEPROM 是焊接在从站板卡上的**物理存储芯片**，通过 **I²C 或 SPI 总线**连接到 ESC。出厂时由驱动器厂商烧录了从站的完整描述信息，是 EtherCAT 从站"身份"持久化保存的地方。

| 特性 | 说明 |
|------|------|
| **位置** | ESC 外部，通过 I²C/SPI 总线连接 |
| **典型型号** | 24LC64（Microchip，64Kbit）、FM24C64（铁电存储器，写入寿命更长） |
| **容量** | 通常 1Kbit ~ 64Kbit（128 ~ 8192 字节） |
| **烧录方式** | 厂商出厂烧录，也可通过主站 `ethercat sii_write` 命令在线烧录 |
| **读取时机** | 上电时 ESC 自动读取前 128 字节；运行时主站按需读取完整内容 |
| **与 ESI 的关系** | ESI 文件是"图纸"（XML），EEPROM 是"实物"（二进制），内容一一对应 |

#### 存储结构

```
EEPROM 地址空间（以 64Kbit = 8192 字节为例）：
┌──────────┬──────────────────────────────────────────────┐
│ 偏移地址  │ 内容                                          │
├──────────┼──────────────────────────────────────────────┤
│ 0x0000   │ ESC 配置区（前 128 字节）                        │
│          │  ├── FMMU 通道数、SM 通道数                     │
│          │  ├── DC 能力（是否支持分布式时钟，支持的模式）      │
│          │  ├── 是否支持 FoE / CoE / SoE / AoE 等         │
│          │  └── 默认站地址                                 │
├──────────┼──────────────────────────────────────────────┤
│ 0x0080   │ 厂商信息区                                      │
│          │  ├── Vendor ID（4 字节，唯一厂商代码）             │
│          │  ├── Product Code（4 字节，产品型号代码）          │
│          │  ├── Revision No.（4 字节，硬件/固件版本）         │
│          │  └── Serial No.（4 字节，序列号）                 │
├──────────┼──────────────────────────────────────────────┤
│ 0x0090   │ 邮箱配置                                        │
│          │  ├── Mailbox 最大大小                            │
│          │  └── 支持的 Mailbox 协议（CoE/SoE/AoE/EoE）      │
├──────────┼──────────────────────────────────────────────┤
│ 0x0100   │ PDO 默认映射                                     │
│          │  ├── RxPDO 映射（索引、子索引、长度、数据类型）     │
│          │  └── TxPDO 映射（索引、子索引、长度、数据类型）     │
├──────────┼──────────────────────────────────────────────┤
│ ...      │ SM 配置、厂商自定义数据 ...                       │
└──────────┴──────────────────────────────────────────────┘
```

#### 调试命令

```bash
# 读取从站 EEPROM 内容并保存到文件
ethercat sii_read -p 1 > slave1_sii.bin

# 使用 hexdump 查看 EEPROM 前 64 字节（厂商信息）
hexdump -C -n 64 slave1_sii.bin

# 在线烧录 EEPROM（危险操作，确认无误后再执行）
ethercat sii_write -p 1 new_config.bin

# 查看从站是否成功识别（基于 EEPROM 内容）
ethercat slave -v -p 1
```

#### 故障影响

| 故障场景          | 现象                                         | 排查方法                             |     |
| ------------- | ------------------------------------------ | -------------------------------- | --- |
| EEPROM 为空（空片） | 从站被识别为 "Unknown / Vendor specific"，无法进入 OP | `ethercat sii_read` 内容全为 0xFF    |     |
| Vendor ID 不匹配 | 主站报 "No matching device found"             | 检查 EEPROM 中 Vendor ID 与 ESI 是否一致 |     |
| PDO 映射损坏      | 从站能进入 OP 但 PDO 数据错位                        | `ethercat pdos -p 1` 检查实际映射      |     |
| EEPROM 物理损坏   | 从站完全无法被识别，或识别信息乱码                          | 用示波器测 I²C 总线，看 ACK/NACK          |     |

### SII（Slave Information Interface）— 从站信息接口

#### 是什么

SII **不是独立芯片**，而是 **ESC 芯片内部的硬件逻辑模块**。它本质上是一个 I²C/SPI 控制器 + 状态机，负责自动读取外部 EEPROM 并让主站能够通过 EtherCAT 帧查询从站信息。

**SII 在 ESC 芯片内部的位置：**

```
┌─────────────────────────────────────┐
│          ESC 芯片 (LAN9252)           │
│                                      │
│  EtherCAT 帧处理引擎                   │
│       │                               │
│  ┌────┴────┐  ┌──────┐  ┌──────┐   │
│  │   SII   │  │ FMMU │  │  SM  │   │
│  │ 读 EEPROM│  │地址映射│  │数据同步│   │
│  └────┬────┘  └──────┘  └──────┘   │
│       │ I²C                          │
└───────┼─────────────────────────────┘
        │
  ┌─────┴─────┐
  │  EEPROM   │
  │ (24LC64)  │
  └───────────┘
```

| 特性 | 说明 |
|------|------|
| **本质** | ESC 内部的 I²C/SPI 控制器 + 状态机 |
| **物理层** | 连接 EEPROM 的 I²C/SPI 总线控制器 |
| **触发方式** | 上电自动读取 EEPROM 前 128 字节；主站可通过寄存器请求读取完整数据 |
| **对外接口** | 主站通过 EtherCAT 帧的 SII 读写命令（寄存器 0x502 ~ 0x50F）访问 SII 数据 |
| **功能** | 将 EEPROM 中的原始二进制数据转换为主站可读的寄存器接口 |

#### SII 工作流程

```
Step 1: ESC 上电复位
        │
Step 2: SII 自动通过 I²C 读取 EEPROM 前 128 字节
        │   → 加载到 ESC 内部寄存器（ESC 配置区）
        │   → ESC 根据配置初始化内部模块数量（FMMU 几个、SM 几个）
        │
Step 3: 主站扫描总线，发送 SII 读取请求
        │   → 主站写寄存器 0x0502 请求读取完整 EEPROM
        │   → SII 逐字节读取 EEPROM，存入响应缓冲区
        │   → 主站从寄存器 0x0504~0x050F 读取数据
        │
Step 4: 主站校验 Vendor ID / Product Code
        │   → 匹配 ESI 文件
        │   → 生成 ENI 配置文件
        │
Step 5: 主站下发 ENI，配置 FMMU、SM、PDO 映射
```

#### ESI ↔ EEPROM ↔ SII 三角关系

```
  ┌──────────────┐       内容相同        ┌──────────────┐
  │  ESI 文件     │ ◄───────┼───────► │  EEPROM 芯片   │
  │  (.xml)       │    二进制格式        │  (24LC64)      │
  │  开发阶段图纸   │                    │  物理实物       │
  └──────┬───────┘                    └──────┬─────────┘
         │  XML 解析                    I²C  │ 物理读取
         ▼                                   ▼
  ┌──────────────────────────────────────────────┐
  │              SII 接口 (ESC 内部硬件)             │
  │  上电自动读取 EEPROM → 主站通过寄存器查询        │
  └──────────────────────┬───────────────────────┘
                         │
                         ▼
  ┌──────────────────────────────────────────────┐
  │               主站获得从站信息                    │
  │  Vendor ID、PDO 默认映射、SM 配置、DC 能力...    │
  └──────────────────────────────────────────────┘
```

> **一句话**：ESI 是"身份证的电子档案"，EEPROM 是"身份证芯片"，SII 是"读卡器"。

### FMMU（Fieldbus Memory Management Unit）— 现场总线内存管理单元

#### 是什么

FMMU 是 **ESC 芯片内部的地址映射硬件单元**。它解决了 EtherCAT 的一个核心问题：**主站发送一帧数据，如何在帧经过每个从站时，让正确的从站只取走属于自己的数据段？**

#### 为什么需要 FMMU

EtherCAT 采用**逻辑寻址**方式：

```
主站视角：一个连续的 4GB 逻辑地址空间

┌────────┬────────┬────────┬────────┬────────┬────────┐
│ Word 0 │ Word 1 │ Word 2 │ Word 3 │ Word 4 │ Word 5 │ ...
└────────┴────────┴────────┴────────┴────────┴────────┘
    ▲        ▲        ▲
    │        │        │
  Slave1   Slave2   Slave3
  FMMU:   FMMU:    FMMU:
  0~1      2~3      4~5
```

- 主站构建一帧数据，包含多个从站的数据段
- 帧经过每个从站时，该从站的 **FMMU 检查**：当前帧中的逻辑地址是否命中我的配置区间？
- 命中 → 取走我的输出数据 / 插入我的输入数据
- 不命中 → 不做任何操作，直接转发

**如果没有 FMMU**：每个从站只能使用物理寻址（逐个从站发送单独帧），效率远低于逻辑寻址的广播方式。

#### FMMU 的寄存器配置

每个 FMMU 通道由以下寄存器定义（约 16 字节）：

```
FMMUx 寄存器组：
┌─────────────────────┬────────┬────────────────────────────┐
│ 寄存器               │ 字节数  │ 说明                        │
├─────────────────────┼────────┼────────────────────────────┤
│ 逻辑起始地址          │   4    │ 在 4GB 逻辑空间中的起始地址     │
│                     │        │ 例：0x00001000              │
├─────────────────────┼────────┼────────────────────────────┤
│ 长度 (bit length)    │   2    │ 占用的位数                   │
│                     │        │ 例：64 (bits) = 8 字节       │
├─────────────────────┼────────┼────────────────────────────┤
│ 逻辑起始位            │   1    │ 在起始地址中的 bit 偏移       │
│                     │        │ 通常为 0                    │
├─────────────────────┼────────┼────────────────────────────┤
│ 数据起始位            │   1    │ 在本地物理地址中的 bit 偏移    │
│                     │        │ 通常为 0                    │
├─────────────────────┼────────┼────────────────────────────┤
│ 本地物理起始地址       │   2    │ 映射到 ESC 内部 RAM 的地址   │
│                     │        │ 例：0x1800 (SM2 的 RAM 区)   │
├─────────────────────┼────────┼────────────────────────────┤
│ 控制/状态             │   1    │ 使能位、方向位（读/写）       │
│                     │        │ bit0: 使能, bit6: 方向       │
└─────────────────────┴────────┴────────────────────────────┘
```

#### 工作流程

| 步骤 | 动作 | 谁执行 |
|:----:|------|:------:|
| 1 | 主站扫描总线，计算每个从站的数据长度 | 主站 |
| 2 | 主站为每个从站分配逻辑地址区间 | 主站 |
| 3 | 主站将地址区间写入每个从站的 FMMU 寄存器 | 主站写入 |
| 4 | 运行时，帧到达从站，FMMU 检查是否命中 | ESC 硬件 |
| 5a | **命中（输出）** → 从帧对应位置拷贝数据到本地 RAM（SM2 区） | ESC 硬件 |
| 5b | **命中（输入）** → 从本地 RAM（SM3 区）拷贝数据到帧对应位置 | ESC 硬件 |
| 5c | **不命中** → 不做任何操作，帧继续转发 | ESC 硬件 |

#### 具体例子

```
总线：2 个从站，CSP 模式，每个从站 8 字节 RxPDO + 8 字节 TxPDO

主站构建的帧逻辑地址布局：
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│ RxPDO_A │ RxPDO_B │ TxPDO_A │ TxPDO_B │ 其他    │
│ 8 bytes │ 8 bytes │ 8 bytes │ 8 bytes │         │
└────┬────┴────┬────┴────┬────┴────┬────┴─────────┘
     │         │         │         │
  FMMU0     FMMU1     FMMU0     FMMU1
  Slave A   Slave B   Slave A   Slave B
  (命中写)   (命中写)   (命中读)   (命中读)

Slave A 的 FMMU 配置：
  FMMU0 (输出/Rx): 逻辑 0x00000000, 长度 64bits, 映射到本地 0x1800
  FMMU1 (输入/Tx): 逻辑 0x00000010, 长度 64bits, 映射到本地 0x1A00
```

#### ESC 芯片支持的 FMMU 数量

| 芯片型号 | FMMU 通道数 | 适用场景 |
|----------|:----------:|----------|
| LAN9252 | 3 | 简单伺服、IO 从站（1 输入 + 1 输出 + 1 备用） |
| AX58100 | 8 | 复杂伺服、多轴驱动器 |
| ET1100 | 8 | Beckhoff 标准从站方案 |
| ET1200 | 3 | 低成本从站（IO、传感器） |

#### 调试命令

```bash
# 查看从站的 FMMU 配置
ethercat fmmu -p 1

# 输出示例：
# FMMU0: LogAddr=0x00001000, Lgth=64, PhysAddr=0x1800, Enable=1
#   逻辑地址 0x1000, 64 bits, 映射到本地物理地址 0x1800, 已使能
# FMMU1: LogAddr=0x00001040, Lgth=64, PhysAddr=0x1A00, Enable=1

# 查看主站分配的逻辑地址空间
ethercat master

# 查看从站的数据长度（决定 FMMU 分配）
ethercat pdos -p 1
```

#### 故障影响

| 故障场景 | 现象 | 排查方法 |
|----------|------|----------|
| FMMU 未使能 | 从站无法接收 RxPDO 数据（控制字无变化） | `ethercat fmmu -p 1` 检查 Enable 位 |
| 逻辑地址冲突 | 多个从站命中同一区间，数据互相覆盖 | 检查主站逻辑地址分配日志 |
| FMMU 数量不足 | 多 PDO 映射时部分数据段无法映射 | 检查 ESC 型号的 FMMU 上限 |

### SM（SyncManager）— 同步管理器

#### 是什么

SM 是 **ESC 芯片内部的硬件通道**（标准 4 个），负责控制主站和从站 MCU **对共享内存的访问权限**。它解决了"两边同时读写同一块内存导致数据错乱"的问题。

#### 四个标准 SM 通道

| 通道 | 方向 | 用途 | 通信类型 | ESC RAM 地址（典型） | 对应章节 |
|:----:|:----:|------|:--------:|:------------------:|:--------:|
| **SM0** | 主站 → 从站 | 邮箱输出（Mailbox Out） | **SDO** | 0x1000 | 一、SDO |
| **SM1** | 从站 → 主站 | 邮箱输入（Mailbox In） | **SDO** | 0x1400 | 一、SDO |
| **SM2** | 主站 → 从站 | 过程数据输出（RxPDO） | **PDO** | 0x1800 | 一、RxPDO |
| **SM3** | 从站 → 主站 | 过程数据输入（TxPDO） | **PDO** | 0x1A00 | 一、TxPDO |

```
物理连接视角：
┌──────┐                  ┌──────────────────────┐
│ 主站  │                  │  ESC                  │
│      │ EtherCAT 帧        │                      │
│      │──────────────────►│  ┌──────────────────┐ │
│      │                  │  │ ESC 内部共享 RAM   │ │
│ RxPDO│──────────────────►│  │                    │ │
│ TxPDO│◄─────────────────│  │  SM0 区 (Mailbox)  │ │◄── SDO 配置
│      │                  │  │  SM1 区 (Mailbox)  │ │──► SDO 应答
│      │                  │  │  SM2 区 (RxPDO)    │ │◄── 控制字/目标位置
│      │                  │  │  SM3 区 (TxPDO)    │ │──► 状态字/实际位置
│      │                  │  └──────────────────┘ │
└──────┘                  └───────────┬───────────┘
                                      │ SPI
                               ┌──────┴──────┐
                               │  MCU        │
                               │ 读 SM2→控制电机│
                               │ 写 SM3→上报状态│
                               └─────────────┘
```

#### SM 的三个核心机制

| 机制 | 工作方式 | 类比 |
|------|----------|------|
| **握手机制** | 写方写完 → 通知读方 → 读方读完 → 通知写方"可再写" | 用对讲机确认"发完了" / "收到了" |
| **数据一致性保护** | 一方正在读取时，另一方写入会被硬件阻止 | 正在读文件时，禁止同时写文件 |
| **中断通知** | 数据到达 / 数据取走后，ESC 向 MCU 发中断信号 | 门铃响了通知你去取快递 |

#### 典型读写时序

```
一个 PDO 周期（1ms @ 1kHz）内：

主站                          ESC                           MCU
 │                             │                             │
 │  (周期开始)                   │                             │
 │                             │                             │
 ├── 写 SM2 RAM (RxPDO) ──────►│                             │
 │  写入: 控制字 + 目标位置       │                             │
 │                             ├── 触发 SM2 中断 ────────────►│
 │                             │                             ├── 进入中断服务函数
 │                             │                             ├── 读取 SM2 数据
 │                             │                             │  得到: 控制字 + 目标位置
 │                             │                             ├── 执行伺服控制算法
 │                             │                             │  位置环 → 速度环 → 电流环
 │                             │                             ├── 写 SM3 RAM (TxPDO)
 │                             │                             │  写入: 状态字 + 实际位置
 │                             │                             └── 退出中断
 │                             │◄── 触发 SM3 中断 ────────────┤
 │                             │                             │
 ├── 读 SM3 RAM (TxPDO) ◄─────│                             │
 │  读到: 状态字 + 实际位置       │                             │
 │                             │                             │
 │  (周期结束，等待下一个 SYNC)    │                             │
```

#### SM 配置寄存器

每个 SM 通道的配置（由主站通过 ENI 写入）：

```
SMx 寄存器组：
├── 物理起始地址 (2 字节)  — 在 ESC 内部 RAM 中的起始地址
├── 长度 (2 字节)          — 该通道占用的字节数
├── 控制寄存器 (1 字节)    — 方向、中断使能、握手机制配置
└── 状态寄存器 (1 字节)    — 当前通道状态
```

#### 调试命令

```bash
# 查看从站的 SM 配置
ethercat sm -p 1

# 输出示例：
# SM0: Addr=0x1000, Len=1024, Control=0x26, Enable=1  ← Mailbox Out
# SM1: Addr=0x1400, Len=1024, Control=0x22, Enable=1  ← Mailbox In
# SM2: Addr=0x1800, Len=64,   Control=0x26, Enable=1  ← RxPDO
# SM3: Addr=0x1A00, Len=64,   Control=0x32, Enable=1  ← TxPDO

# Control 值含义（十六进制）：
#   0x26 = 写保护 + 中断使能（从站可读，主站可写）
#   0x22 = 读保护 + 中断使能（主站可读，从站可写）
#   0x32 = 读保护 + 中断使能（主站可读，从站可写）

# 查看 PDO 分配的 SM 通道
ethercat pdos -p 1

# 检查 SM 通道状态
ethercat reg_read -p 1 0x0800  # SM0 状态
ethercat reg_read -p 1 0x0810  # SM1 状态
ethercat reg_read -p 1 0x0820  # SM2 状态
ethercat reg_read -p 1 0x0830  # SM3 状态
```

#### 故障影响

| 故障场景 | 现象 | 排查方法 |
|----------|------|----------|
| SM 配置未使能 | 从站无法进入 OP，状态卡在 PreOP/SafeOP | `ethercat sm -p 1` 检查 Enable 位 |
| SM 地址/长度错误 | PDO 数据错位或 MCU 读到全 0 | 检查 ESI 文件中 SM 配置段 |
| 中断未配置 | MCU 收不到通知，不处理 PDO 数据 | `ethercat reg_read` 检查 Control 寄存器 |
| SM2/SM3 配置反了 | RxPDO 和 TxPDO 数据互换 | 检查 Control 值（0x26 vs 0x32） |

### MCU（Microcontroller Unit）— 从站微控制器

#### 是什么

MCU 是从站的"大脑"——一颗独立的微控制器芯片（如 STM32、TI C2000），负责运行从站固件。**ESC 只负责通信，MCU 负责应用。**

#### 典型硬件架构

```
                           ┌──────────────┐
                           │   主站 PC    │
                           │  (IgH / 应用) │
                           └──────┬───────┘
                                  │ EtherCAT 帧
                                  │
┌─────────────────────────────────┴────────────────────────────────┐
│                       从站硬件                                   │
│                                                                  │

│  │                                                          │   │
│  │      SII ── I²C ──► EEPROM (存储身份信息)                   │   │
│  │                                                          │   │
│  │      FMMU: 逻辑地址 → 物理地址映射                          │   │
│  │      SM0~3: 数据通道 (邮箱 + 过程数据)                      │   │
│  │                                                          │   │

│  │  │  SM0 [0x1000] Mailbox Out  │ SM1 [0x1400] Mailbox In│   │   │

│  │  │  GPIO (报警灯 / 急停 / 限位开关)                   │   │   │
```

| 特性 | 说明 |
|------|------|
| **位置** | 独立于 ESC 芯片，通过 SPI / 并行总线 / 16 位总线与 ESC 通信 |
| **角色** | ESC 负责"通信"，MCU 负责"应用" |
| **典型型号** | STM32F4/F7 (ARM Cortex-M4/M7)、TI TMS320F28379 (DSP)、Infineon XMC4800 |
| **ESC 通信方式** | 读写 ESC 内部共享 RAM（通过 SM 保障数据一致性） |
| **固件核心功能** | ① 解析 RxPDO ② CiA402 状态机 ③ 伺服三环控制 ④ 写 TxPDO |
| **外设** | 编码器接口、ADC（电流采样）、PWM 输出、GPIO、UART |

#### ESC 与 MCU 的分工对比

| 维度 | ESC (LAN9252 / AX58100) | MCU (STM32 / C2000) |
|------|:-----------------------:|:-------------------:|
| **核心任务** | EtherCAT 通信协议处理 | 应用控制算法执行 |
| **处理内容** | 帧解析、FMMU 地址匹配、SM 同步、中断通知 | CiA402 状态机、伺服三环、编码器采集 |
| **实时性** | 硬件级（纳秒级响应） | 固件级（微秒级响应） |
| **可编程性** | 固定硬件逻辑（不可编程） | 固件可编程（C/C++） |
| **数据量** | 处理整个 EtherCAT 帧 | 只处理分配给本从站的几~几十字节 |
| **故障模式** | FMMU/SM 配置错 → 通信失败 | 固件 bug → 控制异常但通信正常 |

#### 固件主循环伪代码

```c
void main_loop() {
    while(1) {
        // ① 等待 SM2 中断（RxPDO 到达）
        if(esc_sm2_interrupt_received()) {
            // ② 读取 RxPDO
            uint16_t control_word = esc_read_sm2(0x00); // 0x6040
            int32_t target_pos   = esc_read_sm2(0x02); // 0x607A

            // ③ CiA402 状态机处理
            cia402_state_machine(control_word);

            // ④ 运行模式判断
            if(op_mode == OP_CSP) {
                // 周期同步位置控制
                position_loop(target_pos);
            }

            // ⑤ 执行三环控制
            current_pid();
            velocity_pid();
            position_pid();

            // ⑥ 写 TxPDO
            esc_write_sm3(0x00, status_word);   // 0x6041
            esc_write_sm3(0x02, actual_pos);    // 0x6064

            // ⑦ 通知主站数据已就绪
            esc_trigger_sm3_interrupt();
        }

        // ⑧ 非实时任务
        handle_fault_detection();
        update_led_status();
    }
}
```

```
主站应用程序 (工业机器人控制器)
    │
    │  计算目标位置 = 当前角度 + 速度 × 周期

│                                                            │

│                                                            │

│                                                            │

│                                                            │
```

### 五大模块对比总结

| 模块 | 全称 | 物理形态 | 属于 | 核心作用 | 与主站的交互方式 |
|------|------|:--------:|:----:|----------|:----------------:|
| **EEPROM** | Electrically Erasable PROM | 独立存储芯片（24LC64） | 物理层 | 持久化存储从站身份信息 | 主站通过 SII 接口读写 |
| **SII** | Slave Information Interface | ESC 内部硬件逻辑 | ESC 内部 | 自动读取 EEPROM，供主站查询 | 主站通过寄存器 0x502~0x50F 访问 |
| **FMMU** | Fieldbus Memory Management Unit | ESC 内部硬件单元（×3~8） | ESC 内部 | 主站逻辑地址 ↔ 从站本地地址映射 | 主站在初始化阶段配置 |
| **SM** | SyncManager | ESC 内部硬件通道（×4） | ESC 内部 | 主站与 MCU 共享内存的访问同步 | 主站配置 + 运行时握手 |
| **MCU** | Microcontroller Unit | 独立芯片（STM32/C2000） | 应用层 | 运行固件，执行控制算法 | 通过 SM 通道间接与主站交换数据 |

### 故障排查速查

| 症状 | 最可能的原因 | 检查命令 |
|------|-------------|----------|
| 从站无法被识别（Unknown device） | EEPROM 空/损坏 | `ethercat sii_read -p 1` |
| 从站卡在 Init/PreOP | SM 配置错误 | `ethercat sm -p 1` |
| 从站能进 OP 但无控制效果 | FMMU 未使能 | `ethercat fmmu -p 1` |
| PDO 数据全 0 或错位 | PDO 映射或 SM 长度不匹配 | `ethercat pdos -p 1` |
| 通信正常但电机不转 | MCU 固件状态机错误 | 检查状态字 bit0~bit3 + 控制字 |
| 偶发性数据跳变 | SM 握手时序问题 | `ethercat reg_read -p 1 0x08xx` |

### 一句话记忆

> **EEPROM** 存身份 → **SII** 读身份 → **FMMU** 找数据 → **SM** 递数据 → **MCU** 用数据

### 与前面章节的映射

```
章节一：PDO/SDO  ← 数据内容定义
    │
    │  PDO 承载在 → SM2/SM3 通道上
    │  SDO 承载在 → SM0/SM1 通道上
    ▼
章节三：SM 通道  ← 硬件数据通道
    │
    │  SM 通道的数据在帧中的位置由 FMMU 决定
    ▼
章节三：FMMU   ← 地址映射
    │
    │  FMMU 的配置参数来自从站身份信息
    ▼
章节三：SII + EEPROM  ← 身份存储与读取
    │
    │  EEPROM 内容 = ESI 文件二进制
    ▼
章节二：ESI/ENI  ← 配置文件
```
